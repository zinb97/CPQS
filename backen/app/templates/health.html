各列是什么
  • TCP 握手 RTT（主指标）= connectEnd - connectStart，一次 TCP 三次握手的 往返时间，最接近 ping；不含 DNS、不含 HTTP 往返、不含服务端处理。
  • DNS = domainLookupEnd - domainLookupStart，域名解析耗时 （目标是 IP 字面量时通常为 0）。
  • 首字节 = responseStart - requestStart，请求发出到收到首个响应字节， 含服务端处理 + 一次往返。
  • 总耗时 = fetch() 的墙钟时间（DNS + 建连 + HTTP 往返 + 浏览器开销）， 是用户实际感知的打开时延。
  • 采样波动 = 握手 RTT 各次采样的极差，反映链路抖动。
实现与限制
  • 用 fetch(url, {mode:'no-cors'}) 请求采集器的 GET /health（返回 OK）， 用 performance.now() 计时，取 {{ probe_samples }} 次采样的中位数。 no-cors 是必需的：采集器的 /metrics 没有 CORS 头， 普通 cors 模式的跨源请求会被浏览器直接拒掉。
  • 分段耗时来自 Resource Timing API，需要采集器的 /health 返回 Timing-Allow-Origin（新版采集器已加）。没有这个头时浏览器会把分段字段 清零，页面只能给出「总耗时」。
  • 浏览器对跨源且无该头的资源可能只清零部分字段，因此每段都做了「起点 > 0 且终点 > 起点」 的校验，并检查「各段之和 ≤ 该样本总耗时」——不满足的样本整组分段丢弃，避免出现 「DNS 大于总耗时」这类假数据。
  • JavaScript 不能建裸 TCP 连接、不能发 ICMP，浏览器只能发 HTTP 请求， 所以没有任何一列等于纯 ICMP ping。
  • 浏览器会拦截部分请求：页面为 HTTPS 时目标为 HTTP 会被判「混合内容」拦截； 公网页面访问内网地址（192.168.10.x）可能被 Private Network Access 策略拦截。 这类失败会显示具体错误信息。
